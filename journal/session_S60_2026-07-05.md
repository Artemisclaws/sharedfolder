# Session S60 — 2026-07-05
**Topic:** infrastructure

## The Problem
Files were scattered and duplicated across Mac, Drive, and GitHub — Chris asked to consolidate them now that Drive editing works (S59). Scanning for duplicates surfaced something much bigger: the master file map (the thing meant to track where everything lives) was 37+ days stale and had completely missed a real 40-day Lavu data export outage. Chris named the actual root problem out loud: "everything is over-engineered before bedrock," and that he was tired of being asked for information the system already had somewhere.

## Questions We Were Trying to Solve
- Where do files actually live, and how do we stop re-discovering that from scratch every session?
- Why did the existing "update the map at every handoff" rule fail silently for over a month?
- Which real leader or system model actually fits how Chris works, instead of generic productivity advice?
- How does a system account for Chris's personality — flows best with a teammate, gets his best ideas mid-task in a way that derails current work, needs Golfii and Kate taught to plan before executing instead of just being told what to do?
- Is Artie an agent who can just be told things, or does he need code/schedule changes? (Answer: the latter — he's separate automation, OpenClaw, on his own machine.)

## What We Tried That Didn't Work
- A first pass assumed the Drive-side scan should run against local Mac files — had to redirect once Chris clarified he isn't syncing everything locally, only new consolidated files.
- The first full design (v1) was purely mechanical — files, freshness, boot protocol — and left the human/team side out entirely. It also had two real logic bugs: a frozen, never-changing file would have been falsely flagged "stale" forever, and a file that gets touched without new data (which actually happened — `aura_thai_finance`, edited with no new rows) would have shown as "fresh" under a simple file-touch check.
- v1 leaned on five borrowed leadership/systems quotes fairly decoratively. Pushed to identify which one actually fits and why, rather than collect citations.
- The RPG/XP ledger — maintained every handoff for dozens of sessions — turned out to have zero real effect ("it doesn't have any effect on me," Chris's words) and had already been silently skipped at S58 without anyone noticing until this session's audit caught it.

## What We Built
Two Fable-5-authored design documents, both independently fact-checked against live GitHub, Drive, and Mac data rather than taken at face value — every major claim (the session counter fork, the RPG ledger's real staleness, the Obsidian plugins actually installed, the abandoned `_inbox/` folder) was verified directly before being trusted.

v2, the final version: Lean/Toyota as the explicit spine — muda (waste, specifically over-processing) is literally Chris's "over-engineered before bedrock" complaint in its original vocabulary. GTD added for idea capture. The master file map killed entirely — not fixed, replaced — by a small ~25-line REGISTRY of durable IDs plus live tool lookups (search Drive, list the Mac folder, query GitHub directly) for everything else, since a hand-maintained inventory of hundreds of items will always drift at the speed of work. Two named freshness-check fixes: frozen/archival files get no freshness budget (so they can never falsely cry wolf), and freshness gets judged by actual data content where possible, not just file-touch time.

And the new piece: the Fireteam Sprint — a small team loop, GOAL -> HUDDLE (three questions, plan before executing) -> RUN -> DEBRIEF (candid, blameless, peer-level — Pixar's Braintrust, not an Apprentice-style boardroom), sized to work identically whether it's just Chris and Claude today, Golfii and Kate joining for Aura Sweet next, or Aura Thai staff eventually — more copies of the same small loop, never a bigger one. Idea capture doesn't get a new system either — it revives a dormant Obsidian "second brain" that was actually built back in S34 and then abandoned; the note announcing it was found sitting untouched in the very inbox folder it was supposed to serve, which was almost too perfect an illustration of the whole pattern this session exists to fix.

A boot-loader file was produced for Chris to paste into his Claude project's custom instructions, and this session's own handoff was written to model the new discipline it's proposing — including catching, mid-handoff, that S59 had actually been chronicled properly at the time but never handed off, which is exactly the kind of drift this whole redesign targets.

## Key Decisions
- SPRINT.md declared the sole home of the session counter. The fork was real and traceable: a Drive-based file-map copy called itself "S41," a number that had already happened weeks earlier in the real S58 lineage — caused by S59 running its CHRONICLE step but never its handoff step.
- RPG_LEDGER.md retired, evidence-backed, not just preference-backed — replaced by named commitments to teammates, walked out loud at each debrief.
- The master file map (GitHub copy, Drive copy, and the Mac FILE_INDEX table) discontinued entirely — a one-way door, approved by Chris, execution queued for next session.
- Team roster written down as core fact for the first time: Golfii (Chris's wife) and Kate (Golfii's sister), both on Aura Sweet, both ready to help but currently fully directive-dependent — the goal is teaching them to plan before executing, using the huddle itself as the teaching mechanism.
- Claude and Artie are full teammates in the Fireteam Sprint, not backstage tooling — Chris's explicit call, and today Claude is Chris's main team member in practice.
