# Session S69 — 2026-07-28
**Topic:** aura-thai

## The Problem
Chris downloaded 16 new DoorDash/UberEats weekly reports and wanted them filed and their numbers written into `aura_thai_finance`, the live financial model — but Claude had no reliable way to actually edit that Google Sheet. The Drive MCP has no cell-write tool, and the connected Mac folder only exposes Sheets as `.gsheet` link placeholders (Drive Desktop stream mode), not real editable files. EMPIRE_STATUS had been flagging this gap since S65, with a Chrome-pairing workaround that was "usable but flaky." This was the session that had to actually close it.

## Questions We Were Trying to Solve
- Where do these 16 files belong on Drive, and does Claude know the existing filing convention well enough to match it?
- What are the real weekly numbers, and can they be trusted enough to write into a live financial model?
- Is there a durable way for Claude to write into a specific Google Sheet without touching formulas, formatting, or anything else in it?
- Once that exists, how does Chris keep feeding it new reports without repeating this whole ad hoc chat-upload process every time?

## What We Tried That Didn't Work
- First Apps Script deployment came back as a **Library** type, not a Web App — not HTTP-callable at all, and not obvious from the UI why it failed.
- Rebuilt the deployment as a proper Web App — still failed with a generic "Sorry, unable to open the file at this time" error on every POST request, even when Chris tested it himself, logged in, directly in a browser. This looked like it could be an account or permissions problem.
- Ruled that out with a control test: a brand-new, bare-minimum `script.new` project with nothing but `doGet(){return ContentService.createTextOutput("hello")}` — Chris deployed it and it worked instantly via curl. That proved the Google account and Apps Script infrastructure were fine; the ORIGINAL finance-bound project itself was specifically corrupted, almost certainly residue from the earlier Library-type deployment.
- Even after Chris rebuilt the finance project from scratch with the same code, POST requests still failed identically. GET requests worked. Never root-caused why — worked around by switching every call to GET with a URL-encoded `?payload=` query parameter, which the script already supported as a fallback.

## What We Built
`aura_thai_finance_write_endpoint.gs` — an Apps Script Web App bound to `aura_thai_finance` that gives Claude a real, secret-gated HTTP API into the sheet: list every tab, read any range, write a single cell, write a range, or append a row — nothing else in the sheet is ever touched. It's now live and working. Used it to write two real rows into the `Delivery Payouts` tab: UberEats for 7/13–7/19 (31 orders, $1,724.46 gross down to $1,338.43 net after marketplace fee and facilitator tax — cross-checked exactly across three independent sources: the order-level CSV, the item-level CSV, and Uber's own payout PDF) and DoorDash for the same week (91 orders, $4,121.48 gross Subtotal; fees and net payout still pending the Financial Detail report DoorDash doesn't include in the sales export). Also filed 5 DoorDash report zips and 9 of 12 UberEats files into their correct Drive folders, and set up `Finance Dump Folder` (a new Mac folder synced to Drive, with an `Archive` subfolder) as the standing place for Chris to drop future reports — confirmed Claude can move files there into Archive once recorded, even without delete permission. Closed the loop with `REPORTS_NEEDED_checklist.md`, a checkbox list built by actually checking every relevant tab's live content against what's needed, not by assuming — which surfaced that the Lavu Daily Sales (Pretax) tab, stalled since 7/7, is a bigger gap than any of the delivery-platform work this session touched.

## Key Decisions
- Chose GET-with-query-param over continuing to chase the POST failure — a working workaround beat an unexplained blocker, and the script already had the fallback built in.
- Before writing the UberEats numbers, ran a full double-check per Chris's explicit "double check then execute if it checks out" — caught a real commission-percentage miscalculation (19.5% first pass, correct figure 12.54%) before anything touched the live sheet.
- Left the DoorDash net payout row explicitly marked PENDING rather than filling it with an estimate or leaving it silently blank.
- Moving files to Archive, not deleting anything — Claude doesn't have delete permission in the new folder and didn't ask for it, since move alone satisfies the workflow.
