# Session S70 — 2026-08-01
**Topic:** aura-thai, artie-automation

## The Problem
Two threads. Aura Thai's `Daily Sales (Pretax)` tab was stuck at 7/7 — the single biggest gap flagged at S69 close — and Chris wanted to start a real inventory/COGS system "from the ground up." Separately, Chris wanted Artie (his own automation agent, running unattended on a WSL2 machine) actually doing something reliable, and the first idea — Artie reporting to Discord — turned out to be a dead end nobody had noticed: Claude has no Discord connector, so those reports were only ever reaching Chris manually.

## Questions We Were Trying to Solve
- Was there already a Lavu export sitting unprocessed somewhere, or did Chris need to go re-pull it?
- Does an inventory/COGS system need to be built from scratch, or does something already exist in `aura_thai_finance` that just never got used?
- How should vendor invoices actually get captured — photos, email, both — given Taiwah and SJ hand over paper at delivery?
- What can Artie reliably do without failing, given its "one command, one expected output" Bedrock design?
- If Artie can't report anywhere Claude reads, what's the actual mechanism that closes the loop?

## What We Tried That Didn't Work
- First instinct for invoice photos was a shared Google Photos album — checked current Google product behavior before building around it, and as of 2026 Google is actively killing Drive↔Photos auto-sync, and shared albums never synced to Drive in the first place. Would have been a dead end nobody discovered until invoices piled up unread.
- First draft of `invoice_intake_watcher.py` assumed Artie's Gmail/Drive access worked through raw Python OAuth libraries reading token files directly — wrong mechanism. Real access is through the `gog` CLI. Wrote the whole script around an assumption instead of checking first, and said so explicitly rather than shipping it silently.
- Both new cron entries initially omitted `source ~/.bashrc` before running — cron's minimal PATH doesn't include wherever `gog` actually lives, which would have made the invoice watcher fail silently every morning. Caught by comparing against the existing `token_refresh.py` cron entry, which already had the same fix for the same reason.

## What We Built
Closed the Daily Sales gap: found Chris had already dropped a Lavu CSV (7/8–7/27) into Finance Dump Folder on 7/28 that nobody had processed. Cross-checked every day's numbers against the CSV's own totals row before writing anything, then wrote all 20 rows into the live sheet — current to 7/27 now, inside the 7-day freshness budget. Designed the inventory/COGS system on top of infrastructure that already existed but sat empty: `Invoice Log`, `Dish Map`, and `COGS by Dish` tabs, built by an earlier session, zero rows in any of them. Wrote a full SOP, got Chris to email Taiwah and SJ pointing them at `artemisclaws+invoices@gmail.com` as the primary capture path, and created an `Invoices Dump Folder` in Drive as the photo fallback for anything that doesn't arrive by email.

For Artie: built and proved two new automation SOPs, live, end to end, on Artie's actual machine (not just tested from Claude's own sandbox). SOP 05 `freshness_heartbeat.py` checks `Daily Sales (Pretax)` and `Delivery Payouts` freshness daily via plain HTTP against the existing sheet endpoint — no OAuth needed, so it was fully provable before Artie ever touched it. SOP 06 `invoice_intake_watcher.py` watches Gmail and the new Drive folder for incoming vendor invoices, rebuilt around real `gog` CLI syntax once Chris pulled the actual `--help` output and sample JSON live from the machine. Along the way, found and fixed a dead `gog` OAuth refresh token (re-authorized live via TeamViewer) and created `artie/ARTIE_REPORTS.md` — a GitHub log Artie's scripts write to, since that's the only channel that actually reaches Claude.

## Key Decisions
- Never guessed at `gog`'s command syntax or the shape of Artie's credentials — asked Chris to pull real `--help` output and real sample JSON before writing a line of the final script.
- Kept the two new Artie scripts to pure existence/count checks, not extraction — matches the Bedrock rule of proving one simple thing before layering anything with real judgment calls on top.
- Chose to fix the stale `Lavu Drive folder` REGISTRY pointer (superseded by Finance Dump Folder months ago, never updated) rather than let it keep false-flagging red forever.
- Required a manual first test run on Artie's real machine for both scripts before adding either to cron — same two-step pattern as the existing platform-report SOP.
